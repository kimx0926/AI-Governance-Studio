# Enterprise AI Governance Studio

A working implementation of an enterprise AI governance workflow: **intake → deterministic risk scoring → risk-to-Playbook translation → policy-as-code generation → MCP tool-calling gate → HITL audit trail.**

> Built by [Minsun Kim](https://linkedin.com/in/minsun-kim0926) as a portfolio project. Not affiliated with any employer named in this repo's design references.

## Why this exists

Most "AI governance" demos stop at generating a text summary of applicable regulations. This project answers two questions in sequence instead: **"risk identified — now what do we *do* about it?"** (F-07, the Playbook) and **"when the agent tries to do something, what stops it?"** (the MCP gate). Both answers are produced by deterministic code, not an LLM call — see Design Decision T-06 in the PRD for why.

## Information architecture

The live demo ships 5 pages, matching the reference wireframe (`docs/wireframes/`):

| Page | What it shows | Backed by |
|---|---|---|
| Overview | Portfolio-wide risk distribution, recent activity, top systems by risk, plus a drill-down into any selected use case (reuses the Playbook card — not a duplicate feature) | `/api/overview` |
| New Intake | The F-01 form. Submitting runs the full pipeline and reveals the same analysis card inline | `/api/intake` |
| Risk Assessment | Browse the risk profile of any past intake — a history surface distinct from Overview's snapshot and Intake's live run, but rendering the identical card | `/api/use-case/{name}` |
| Audit Trail | Every assessment logged with its most recent MCP gate action, level, and owner | `/api/audit` |
| Playbooks | The F-07 Playbook, browsable per use case | `/api/use-case/{name}` |

## The 8 risk factors — and why the names changed

F-02 now scores exactly the 8 dimensions named in the PRD (Personal Data / Privacy, Sensitive Data / Enterprise IP, Autonomous Decision Making, High-Impact Domain, External Users / Reputation, Model Transparency, Security Exposure, Third-Party Dependency — weights 20/20/20/20/15/15/10/10 = 130). Earlier builds of this project used a different 8-factor set (`customer_facing`, `contains_pii`, etc.) written before the PRD's Risk Matrix section existed. This build reconciles code to PRD — the New Intake form's checklist is now *literally* the same list the engine scores, not an approximation of it.

## What's built vs. what's intentionally left out

Two things the wireframe suggested were deliberately **not** implemented, and are documented rather than silently dropped:

- **"System Quality Telemetry" (groundedness, hallucination rate, latency, cost per system)** — this would require real production LLM traffic to measure honestly. Fabricating these numbers would violate the same evaluation-honesty standard (PRD Section 06A) that this project has followed throughout. The Overview page shows a card explaining the omission instead of a fake table.
- **A "Confidence %" score** — F-02 is explicitly non-probabilistic ("Not Machine Learning. Not Probabilistic. 100% Deterministic."), so a confidence percentage has no valid meaning here. Replaced with the actual score (`n/130`).

"Active" and "Completed" counts on Overview *are* real, computed from whether a use case has a recorded HITL decision (F-04) — not placeholders.

## Running it

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # optional — leave ANTHROPIC_API_KEY blank to run on mock responses
uvicorn app.main:app --reload --port 8000

# frontend — open frontend/index.html directly (calls http://localhost:8000)
```

```bash
cd backend && pytest -v   # 13 tests, no API key needed
```

## Architecture

```
Intake (F-01) → Risk Score (F-02) → Playbook (F-07) → Policy Manifest (F-03) → Audit Save → MCP Gate
```

LangGraph orchestrates this as a single `StateGraph` with a fixed edge sequence (`backend/app/langgraph_workflow.py`). See `docs/ARCHITECTURE.md` and the PRD's Design Decision T-06 for why the MCP policy manifest and the Playbook are both generated by deterministic code, with the LLM scoped to narrative generation only.

## Honest scope notes

- Portfolio project, not a production system. In-memory audit store, resets on restart.
- The MCP gate simulates tool-call interception; it does not run a real MCP server against live tools.
- F-10 (Technical Evidence) Tier 1 fields (repository URL, foundation model, enterprise policies) are stored on intake but not yet scored or analyzed — see the PRD for the staged Tier 1/2/3 rollout, including why Tier 3 (repository-level code remediation) is an explicit non-goal, not a roadmap item.
